## 4. Exact behavior to preserve
- Existing strict incoming peer schema/defaults and AAUI authenticated dispatch: from `aaui`, to `pserver`, payload type `demo.resource-selection`. No new kind restriction. Strict selection schema: browserProfileId, proxyId, accountId all trimmed strings of length 1–150, no additional properties. Exact invalid ACK texts: `Invalid resource selection envelope` and `Invalid resource selection IDs`, code `INVALID_MESSAGE`.
- Await store.save before notification, scheduling and successful receipt. On save rejection return `{ok:false,code:'DELIVERY_FAILED',error:'Could not persist resource selection'}`; no notification or deferred work. Store assigns its own UUID, createdTime and pending delivery status. Preserve distinction between selection record ID and peer message ID.
- Publish original pending record with `resource-selection:updated` before scheduling. Preserve existing message ID selection (provided or generated after initial publication), cloned original payload, numeric timestamp, envelope defaults and `{ok:true,status:'received',data:envelope}`. Do not substitute normalized stored selection into outbound or ACK payload. Receipt does not await PServer delivery. No extra readiness gate before receipt or before M10 beyond the existing processor behavior.
- Schedule exactly one deferred operation using runtime setImmediate; call M10 process with original parsed envelope plus captured ID and authenticated `aaui`. On success classify forwarded, on failure classify forwardFailed with Error.message or String(error). Preserve diagnostics. Do not introduce retry, outbox, durability or idempotency changes.
- Crucial independent error boundaries: await updateDelivery(record.id,status,reason) separately after forwarding outcome. Failure to persist status must NEVER reclassify successful PServer delivery or prevent the final AAUI update. Publish `{...record,deliveryStatus:status,...(reason ? {deliveryError:reason} : {})}` even if status storage fails. Preserve omission of empty reason in notification and store fallback `Delivery failed` for failed status with falsy reason. Do not force the in-memory update and persisted snapshot to agree when sidecar write fails. Preserve current AAUI lookup at each notification, not capture original socket. No change to notification exception semantics without explicit evidence/approval.
- M13 owns successful snapshot projection `{records,timestamp:Date.now()}` from listRecent(50). Infrastructure owns current-connection checks and emission to original requesting AAUI only. Check original identity before query; after await verify connected AND same current AAUI for success and failure. Fallback remains `{records:[],timestamp:Date.now(),error:'Could not load saved selections'}`. Preserve `resource-selection:snapshot` and `resource-selection:refresh`, initial connect/reconnect wiring, presence, welcome, ping and task snapshots. A small focused adapter is acceptable; do not generalize M12 snapshot helper in this phase.
