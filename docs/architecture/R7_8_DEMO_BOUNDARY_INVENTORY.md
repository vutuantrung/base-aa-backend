### Prior classification evidence for the unresolved modules

The R6.4.A report explicitly left M12 APP-versus-DEMO unclassified while identifying `peer-gateway.ts`, M04’s PServer ingress facade, tests/docs, and playground flows as consumers. R6.4.B likewise retained M13 as TBD and documented the demo-gated gateway/UI/PServer path while extracting only a testable workflow seam. R6.4.C and R6.4.D each separated neutral repository contracts from the SQLite adapter/M07 and M02 composition, but explicitly left M14 and M15 APP-versus-DEMO unresolved. R6.4.D’s source audit found no example/playground repository consumer; R6.4.C found no playground-specific session repository consumer. These reports support treating M14/M15 as APP candidates without implying external demand or overriding the recorded TBD decisions.

## Known discovery limits

- AAB API and Socket.IO contracts have no complete external client inventory. “No tracked caller” is not proof that an API can be removed.
- The application `/peers` and `/ws` contracts are observed from source/local tests; there is no production PServer/EServer/SServer service or deployed filesystem in this checkpoint.
- Static checker edges omit cross-process message semantics and dynamic Socket.IO composition; the runtime dependency document supplements but does not turn them into code imports.
- Tests characterize local behavior, not production hosting, power-loss durability, remote receiver persistence, or exactly-once business completion.
- R7.7 manifest classifications are review aids. The R7.7 Full gate passed on Node 22.23.5: 253 backend and 32 playground tests; architecture, typecheck, build and SQLite preflight passed.
