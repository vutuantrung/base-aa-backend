# R7.2.0 Reliability Risk Inventory — Connection and Session State

## Scope and evidence rules

Audit-only snapshot at R7.2.0 baseline `d14a5929a6016f05d23e7f9954231da364483382`; closure evidence was reviewed against committed source HEAD `dce8537cff84d0968589fafa9e55dac8c52c518b`. This covers TD02–TD04 and only adjacent state needed to explain them. It does not authorize behavior changes. “Observed” means directly visible in source or asserted by a test; “Hypothesis” means a plausible race with no reproduction; “Unverified” means an outcome lacks deterministic evidence. Qualitative impact/likelihood are not measurements.

Preserve: public socket/protocol contracts; M06 peer IDs and instance semantics; the distinction between transport-connected and session-ready; current `PeerMessageAck` codes and ACK behavior; M12/M13 deferred workflow behavior. No production PServer or real runtime data is used.

## R7.2 closure review disposition

The R7.2.A.4, B, B.1, C and C.1 checkpoints are complete at the source level reviewed on `dce8537cff84d0968589fafa9e55dac8c52c518b`. Fresh Node 22.23.5 closure verification passed: focused TD02–TD04 suite 43/43, architecture rules, typecheck, build, backend 177/177, playground 32/32 and diff check. The architecture checker still reports zero file runtime SCCs and the M10↔M12↔M13 module runtime SCC for review; this is not a new R7.2 finding.

- **TD02 remains OPEN (Option B).** A.4 is local Socket.IO loopback evidence for a deliberately added downstream rejecting middleware while `/session` shares the Engine.IO transport. It proves retained identity and duplicate retry rejection in that controlled scenario, not spontaneous abort reachability in the production single-middleware composition and not cleanup. Revisit only when a supported namespace-scoped terminal lifecycle boundary or newly validated equivalent can guarantee rollback while preserving atomic duplicate rejection and connection-ID-safe cleanup.
- **TD03 is partially remediated, not closed.** B.1 deterministically verifies generation invalidation on connect/disconnect/close, stale ACK suppression, readiness gates and unchanged retained-ID failed-resume behavior. Remote PServer timings and rejected-resume semantics are unverified; already-started outbound delivery is not cancelled.
- **TD04 is remediated under deterministic characterization.** C.1 tests logical-instance binding before transformation, same-instance connection replacement, no substitution to another instance, initial offline/ambiguity classifications and delivery-failure mapping, without changing the public message envelope. Real socket/topology timing and the non-atomic identity-lookup-to-send interval remain residual limits.

Recommended disposition: **CONDITIONALLY CLOSED**, pending reviewer approval. This closes the bounded R7.2 characterization/remediation scope, not every reliability risk. R7.3 may be considered as an independently authorized phase because TD02’s unresolved admission boundary and TD03’s remote protocol limits are documented and R7.2 did not change workflow or public message contracts; this inventory does not authorize starting it.
