# R7.2.0 Reliability Risk Inventory — Connection and Session State

## Scope and evidence rules

Audit-only snapshot at `main` HEAD `d14a5929a6016f05d23e7f9954231da364483382`. This covers TD02–TD04 and only adjacent state needed to explain them. It does not authorize behavior changes. “Observed” means directly visible in source or already asserted by a test; “Hypothesis” means a plausible race from ordering with no reproduction; “Unverified” means current behavior can be traced but a race outcome lacks a deterministic test. Qualitative impact/likelihood are not measurements.

Preserve: public socket/protocol contracts; M06 peer IDs and instance semantics; the distinction between transport-connected and session-ready; current `PeerMessageAck` codes and ACK behavior; M12/M13 deferred workflow behavior. No production PServer or real runtime data is used.

## Coverage boundary and excluded adjacent issue

TD05 no-ACK ingress is explicitly R7.3 and is not assessed here. M03/M04 tests assert current ACK contracts; no ACK code is changed or proposed. This inventory does not assess workflow persistence/deferred-work durability, shutdown, broad module ownership, production PServer behavior, or the R7.1 checker SCC/limitations.

## Recommended test-first sequence

1. **R7.2.A — namespace handshake/identity lifecycle (TD02).** A.4 passes while positively characterizing identity retention and duplicate retry rejection after controlled downstream middleware rejection. Architecture owner selected Option B: retain all-aborts cleanup and defer remediation until a supported namespace-scoped terminal boundary can preserve atomic duplicate errors and observe rollback outcomes. Spontaneous abort in current production composition remains unverified; TD02 remains OPEN.
2. **R7.2.B — PServer registration generation and resume outcomes (TD03).** Extend the fake transport with deferred ACK resolvers. Characterize old ACK after disconnect, old ACK during a later connection, and missing/negative/rejected resume after an established session. Preserve transport-connected versus session-ready. Obtain explicit policy for stale ACK and rejected-resume handling before any change.
3. **R7.2.C — destination topology during transform (TD04).** Use a controlled transformer promise and mutable fake directory/delivery to characterize removal, same-instance replacement, and newly ambiguous untargeted EServer. Record current ACK codes and selected connection. Obtain explicit policy for connection affinity and ambiguity classification before a fix.

Order is based on state dependency and isolation: establish inbound identity lifecycle first, then outbound PServer session lifecycle, then message delivery against changing peer topology. These are proposed audit/test checkpoints, not authorization to implement fixes.
