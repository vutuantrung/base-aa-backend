## Import/ownership caveats
M02 is composition root; avoid service locator and new runtime cycles. Its current public return shape and consumer evidence are audited in [APPLICATION_SURFACE_INVENTORY.md](APPLICATION_SURFACE_INVENTORY.md); R7.6.B preserves that shape. `ApplicationCoordinator` is M02-owned and injected via the narrow `shared/contracts/application-admission.ts` port into M05/M07/M09. `main.ts` alone owns process signals. M12/M13 retain workflow/store/runner ownership; the shared runner exposes lifecycle settlement and uses an optional store lease capability, while M17 file stores enforce same-directory single runner in-process in addition to OS writer lock. M01/M02 consume canonical PServer value/config types from M04 contracts; M03 connector preserves legacy exports. M04 owns the canonical transport port; M03 adapter imports it by type and keeps legacy exports. The protocol no longer imports infrastructure. M08 clients depend type-only on neutral `ConnectableMessageClient`; maintained consumers use `infrastructure/integration-clients/index.ts`. `shared/transport/connectable-client.ts` remains the one explicit shared-to-infrastructure runtime re-export exception for compatibility. M06 logical state is not a second socket map. M10 imports M11 execution; M11 imports M10 contract types. M12/M13 import M10 schema/types, not gateway classes. Compatibility re-exports `peer-messaging/{task-file-store,resource-selection-store}.ts` point to domain owners. M14/M15 legacy adapter files re-export canonical neutral types. M07 depends on neutral M14–M16 contracts; M02 exposes existing concrete handles. Architecture checker reports existing M10↔M12↔M13 module runtime SCC; no new file-level SCC is allowed. M17 owns SQLite lifetime, M02 coordinates app lifecycle; domain repositories own records, not separate DB handles. Cross-cutting auth distributed; no M19 needed. See debt registry and R7.6.B report for evidence limits.
