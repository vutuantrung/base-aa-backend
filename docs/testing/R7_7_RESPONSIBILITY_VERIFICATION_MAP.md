## Fixtures and selection guidance

Current reusable assets include `tests/support/mock-pserver.ts`, `tests/helpers/memory-reliable-store.ts`, `tests/helpers/reliable-crash-child.ts`, `testing/shared/create-peer-server.mjs`, `testing/shared/mock-vm-info.mjs`, `testing/shared/scheduled-peer-message.mjs`, `testing/shared/resource-selection.cjs`, `testing/shared/task-flow.cjs`, and `testing/aaui/dashboard-state.js`. Lifecycle tests also contain local bounded barrier helpers; there is no shared universal harness.

Future fixture ownership recommendation: the owning test file or narrow fixture module creates and closes listeners; each test owns a unique temporary root; environment changes restore exact prior values in `finally`/hooks; child harness owns bounded IPC/exit cleanup; memory stores stay pure and deterministic; fixture imports flow from narrow support modules, not a cross-suite omnibus fixture. This recommendation is pending D02 approval.

Examples for a future agent selector (not a complete analyzer):

- Change to `src/modules/task-workflow/task-workflow.ts` / M12: fast `task-workflow.test.ts`; integration `f09-task-result-receipt.test.ts`, `task-received-routing.test.ts`, `application-peer-ack-drain.test.ts` when its operation is affected; full backend, crash and playground gates before merge.
- Change to `src/shared/persistence/atomic-json-record-store.ts` / M17-support: `reliable-outbox.test.ts`, `reliable-crash-process.test.ts`; full backend and playground, with Node/native dependency and local filesystem requirements recorded.
- Change to `src/infrastructure/http/http-api-router.ts` / M07: HTTP route contract files (`http-gateway`, `session-http-api`, `process-usage-http-api`, `aa-catalog-boundary` as relevant), then full gates.
