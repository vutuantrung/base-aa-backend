## 5. Persistent state impact

- **Peer identities in durable payloads and records:** F08/F09 outbound envelopes carry `from`, `to` peer values; prepared outbound messages can be committed inside reliable records (`src/modules/task-workflow/task-workflow.ts:91-120,153-174`). M13 stores original outbound selection message and sender context; its dedupe key is explicitly `M13:aaui:<message-id>` and fingerprint input includes authenticated sender `'aaui'` (`src/modules/resource-selection/resource-selection-workflow.ts:59-66`). These values affect deduplication behavior and must be treated as persisted contract data.
- **Dedupe/fingerprint inputs:** M12 F08 key is `F08:<task-id>` and fingerprint is over `{task,targetId}` (`task-workflow.ts:78-86`); M12 F09 uses its operation key and fingerprint over task/source instance (`:129-174`). M13 key includes old peer identity; fingerprint includes authenticated peer identity and message fields. `fingerprintReliableValue` hashes stable JSON with SHA-256 (`src/shared/persistence/atomic-json-record-store.ts:87-109`), and record checksum/hash paths protect persisted record identity (`:515-519`). Changing peer text changes M13 dedupe keys/fingerprints and serialized outbound values. **M12/M13 ownership remains TBD.**
- **Prepared outbound messages / durable outbox:** `JsonTaskFileStore` stores legacy task files in `./data/tasks` and outbox in `<directory>/.r7.5-outbox` (`src/modules/task-workflow/task-file-store.ts:45-60`); resource selection uses `./data/resource-selections` with same subdirectory (`src/modules/resource-selection/resource-selection-store.ts:50-60`). Legacy records and current reliable outbox are distinct; changing env prefixes alone does not relocate existing directories, but fresh AS deployment must explicitly point to an empty/new state location.
- **Persistent directories and filenames:** task files use task IDs and `.json`/result forms; selection records use ID-derived files and delivery sidecars. Directory names `data/tasks`, `data/resource-selections`, `.r7.5-outbox`, record formats and generic table names remain. Existing DB/data must never be automatically deleted, migrated or replayed. NP-04 requires operator-controlled fresh state; NM.3 must specify new AS deployment path and explicit operator selection of fresh directories before startup. Do not add auto-cleanup or implicit import/replay.
- **SQLite:** table/column names `Session`, `ProcessUsage`, `AaConnection`, `AaBrowser`, `AaExtension`, `AaActivity`, `AaTask`, `extension_id` are preserved under NP-08. No table migration is in scope.
